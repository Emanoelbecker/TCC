DICIONÁRIO DE DADOS — SISTEMA DE GERENCIAMENTO

1. TABELA ADMINISTRADOR

Campo: idAdministrador
Tipo: INT
Restrições: PK, AUTO_INCREMENT
Exemplo: 1
Descrição: Identificador único do administrador.

Campo: nomeUsuario
Tipo: VARCHAR(50)
Restrições: NOT NULL, UNIQUE
Exemplo: admin
Descrição: Nome utilizado para realizar o login.

Campo: senhaHash
Tipo: VARCHAR(255)
Restrições: NOT NULL
Exemplo: $argon2id$...
Descrição: Hash da senha do administrador. A senha original não deve ser armazenada diretamente no banco.


2. TABELA CLIENTE

Campo: idCliente
Tipo: INT
Restrições: PK, AUTO_INCREMENT
Exemplo: 1
Descrição: Identificador único do cliente.

Campo: nome
Tipo: VARCHAR(150)
Restrições: NOT NULL
Exemplo: Fulano da Silva
Descrição: Nome do cliente.

Campo: cpf
Tipo: VARCHAR(11)
Restrições: UNIQUE
Exemplo: 12345678909
Descrição: CPF do cliente.

Campo: cnpj
Tipo: VARCHAR(14)
Restrições: UNIQUE
Exemplo: 12345678000100
Descrição: CNPJ do cliente.

Campo: representante
Tipo: VARCHAR(150)
Restrições: -
Exemplo: Siclano da Silva
Descrição: Representante do cliente, quando aplicável.

Campo: email
Tipo: VARCHAR(150)
Restrições: -
Exemplo: emailcriativo@gmail.com
Descrição: E-mail do cliente.

Campo: telefone
Tipo: VARCHAR(20)
Restrições: -
Exemplo: 11912345678
Descrição: Telefone do cliente.

Campo: nomeFantasia
Tipo: VARCHAR(150)
Restrições: -
Exemplo: Empresa Silva
Descrição: Nome fantasia da empresa.

Campo: observacao
Tipo: TEXT
Restrições: -
Exemplo: Cliente possui alergia a amendoim
Descrição: Observações gerais sobre o cliente.

Campo: rua
Tipo: VARCHAR(150)
Restrições: -
Exemplo: Dom Pedro
Descrição: Rua do endereço.

Campo: numero
Tipo: INT
Restrições: -
Exemplo: 200
Descrição: Número do endereço.

Campo: cep
Tipo: CHAR(8)
Restrições: -
Exemplo: 20040002
Descrição: CEP do endereço.

Campo: uf
Tipo: CHAR(2)
Restrições: -
Exemplo: RS
Descrição: Unidade federativa do endereço.

Campo: bairro
Tipo: VARCHAR(100)
Restrições: -
Exemplo: Centro
Descrição: Bairro do endereço.

Observação:
O cliente poderá ser pessoa física ou jurídica. A regra de negócio deve definir se será obrigatório informar CPF ou CNPJ.


3. TABELA PRODUTO

Campo: idProduto
Tipo: INT
Restrições: PK, AUTO_INCREMENT
Exemplo: 1
Descrição: Identificador único do produto.

Campo: nome
Tipo: VARCHAR(150)
Restrições: NOT NULL
Exemplo: Bolacha de limão
Descrição: Nome do produto.

Campo: dataLote
Tipo: DATE
Restrições: -
Exemplo: 2025-12-22
Descrição: Data relacionada ao lote.

Campo: dataValidade
Tipo: DATE
Restrições: -
Exemplo: 2027-06-12
Descrição: Data de validade do produto.

Campo: dataFabricacao
Tipo: DATE
Restrições: -
Exemplo: 2025-06-02
Descrição: Data de fabricação do produto.

Campo: observacao
Tipo: TEXT
Restrições: -
Exemplo: Contém ovos.
Descrição: Observações sobre o produto.

Campo: foto
Tipo: VARCHAR(2048)
Restrições: -
Exemplo: https://...
Descrição: Link/URL da foto do produto.

Campo: valor
Tipo: DECIMAL(10,2)
Restrições: -
Exemplo: 20.30
Descrição: Valor do produto.

Campo: valorUnidade
Tipo: DECIMAL(10,2)
Restrições: -
Exemplo: 10.15
Descrição: Valor por unidade.

Campo: ingredientes
Tipo: TEXT
Restrições: -
Exemplo: Ovos, farinha, etc.
Descrição: Ingredientes do produto.

Observação:
É necessário definir nas regras de negócio exatamente a diferença entre "valor" e "valorUnidade".


4. TABELA VENDA

Campo: idVenda
Tipo: INT
Restrições: PK, AUTO_INCREMENT
Exemplo: 1
Descrição: Identificador único da venda.

Campo: idCliente
Tipo: INT
Restrições: FK, NOT NULL
Exemplo: 1
Descrição: Identificador do cliente que realizou a compra.

Relacionamento:
Venda.idCliente -> Cliente.idCliente

Campo: localEntrega
Tipo: VARCHAR(255)
Restrições: -
Exemplo: Supermercado Gisele nº 600
Descrição: Local de entrega da venda.

Campo: dataPedido
Tipo: DATE
Restrições: NOT NULL
Exemplo: 2025-12-19
Descrição: Data em que o pedido foi realizado.

Campo: dataEntrega
Tipo: DATE
Restrições: -
Exemplo: 2025-12-20
Descrição: Data prevista ou realizada da entrega.

Campo: valorTotal
Tipo: DECIMAL(10,2)
Restrições: -
Exemplo: 7200.00
Descrição: Valor total da venda.

Campo: observacao
Tipo: TEXT
Restrições: -
Exemplo: Essa venda foi difícil...
Descrição: Observações da venda.


5. TABELA ITEM_VENDA

Campo: idItemVenda
Tipo: INT
Restrições: PK, AUTO_INCREMENT
Exemplo: 1
Descrição: Identificador único do item da venda.

Campo: idVenda
Tipo: INT
Restrições: FK, NOT NULL
Exemplo: 1
Descrição: Identificador da venda à qual o item pertence.

Relacionamento:
ItemVenda.idVenda -> Venda.idVenda

Campo: idProduto
Tipo: INT
Restrições: FK, NOT NULL
Exemplo: 1
Descrição: Identificador do produto vendido.

Relacionamento:
ItemVenda.idProduto -> Produto.idProduto

Campo: quantidade
Tipo: INT
Restrições: NOT NULL
Exemplo: 12
Descrição: Quantidade do produto vendida.

Campo: valorUnitario
Tipo: DECIMAL(10,2)
Restrições: NOT NULL
Exemplo: 20.30
Descrição: Preço unitário utilizado naquela venda.

Observação:
O valorUnitario é armazenado no ItemVenda para preservar o preço utilizado no momento da venda, mesmo que o preço atual do produto seja alterado posteriormente.


6. RELACIONAMENTOS ENTRE AS TABELAS

Cliente 1:N Venda

Um cliente pode possuir várias vendas.
Uma venda pertence a um cliente.

Venda 1:N ItemVenda

Uma venda pode possuir vários itens.
Um item pertence a uma única venda.

Produto 1:N ItemVenda

Um produto pode aparecer em vários itens de venda.
Um item de venda referencia um único produto.

Representação:

Cliente
    |
    | 1:N
    v
Venda
    |
    | 1:N
    v
ItemVenda
    ^
    | N:1
    |
Produto


7. RESUMO DAS REGRAS DE TIPOS

CPF: VARCHAR(11)
CNPJ: VARCHAR(14)
Telefone: VARCHAR(20)
CEP: CHAR(8)
UF: CHAR(2)

Valores monetários: DECIMAL(10,2)

Datas: DATE

Identificadores: INT AUTO_INCREMENT

Senhas: armazenadas somente como hash, utilizando algoritmo apropriado.


8. PRINCIPAIS REGRAS DE NEGÓCIO

RN01 - Somente o administrador poderá acessar e utilizar o sistema.

RN02 - A senha do administrador nunca será armazenada em texto puro.

RN03 - O nome de usuário do administrador deve ser único.

RN04 - Cada cliente deve possuir um identificador único.

RN05 - CPF não pode se repetir entre clientes.

RN06 - CNPJ não pode se repetir entre clientes.

RN07 - Uma venda deve pertencer a um cliente.

RN08 - Uma venda deve possuir pelo menos um item.

RN09 - Um item de venda deve possuir uma quantidade maior que zero.

RN10 - Um item de venda deve estar associado a um produto existente.

RN11 - O valor total da venda deve ser calculado a partir dos itens da venda.

RN12 - O valor unitário registrado em ItemVenda deve representar o preço utilizado naquela venda.

RN13 - Valores monetários devem utilizar duas casas decimais.

RN14 - Os identificadores serão armazenados como números inteiros; zeros à esquerda, quando necessários para exibição, devem ser aplicados somente na interface.

RN15 - O sistema terá no máximo aproximadamente 1.000 clientes registrados e não será projetado para mais de 100 usuários simultâneos.
